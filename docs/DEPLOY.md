# 微信云开发部署手册

## 1. 准备小程序

1. 在微信公众平台注册小程序并取得 AppID。
2. 用微信开发者工具导入仓库根目录（不是 `miniprogram` 子目录）。
3. 将根目录 `project.config.json` 中的 `touristappid` 替换为正式 AppID。
4. 在工具栏点击「云开发」并创建环境。基础版即可开始联调。

应用初始化使用：

```js
wx.cloud.init({ env: wx.cloud.DYNAMIC_CURRENT_ENV, traceUser: true })
```

开发者工具当前选择哪个云环境，小程序与云函数就使用哪个环境，不需要修改源码。

## 2. 创建数据库集合

在云开发控制台创建以下集合：

| 集合 | 用途 |
| --- | --- |
| `users` | 用户昵称、偏好、当前房间 |
| `rooms` | 邀请码、两位成员、上次拍板人 |
| `favorites` | 情侣共同收藏 |
| `spins` | 每次转盘候选与云端结果 |
| `records` | 已确认的投喂日记 |

将数据库安全规则设为：

```json
{
  "read": false,
  "write": false
}
```

云函数拥有服务端访问能力，不受客户端规则限制。不要改成全员可读写。

## 3. 创建索引

在云开发控制台「数据库 → 索引」中创建：

| 集合 | 字段 | 类型 |
| --- | --- | --- |
| `rooms` | `inviteCode` 升序 | 唯一索引 |
| `favorites` | `roomId` 升序、`createdAt` 降序 | 组合索引 |
| `spins` | `roomId` 升序、`createdAt` 降序 | 组合索引 |
| `records` | `roomId` 升序、`eatenAt` 降序 | 组合索引 |
| `records` | `roomId` 升序、`decisionType` 升序 | 组合索引 |

仓库中的 `database.collections.json` 也列出了相同配置。索引刚创建时需要等待状态变为「正常」。

## 4. 部署云函数

在开发者工具的 `cloudfunctions` 目录中，依次右键：

- `auth`
- `room`
- `favorites`
- `spin`
- `records`
- `profile`

每个都选择「上传并部署：云端安装依赖」。部署完成后，在云开发控制台确认六个函数均存在。

> 云函数依赖 `wx-server-sdk 4.0.2`，不需要把本地 `node_modules` 上传到 Git。

## 5. 真机闭环验收

建议准备两个开发者/体验者微信账号：

1. A 首次进入，首页点「心意绑定 → 我来邀请」，生成 6 位码。
2. B 通过分享卡片进入，或在「我有邀请码」中输入 6 位码。
3. A 下拉刷新，确认双方状态均为「已连接」。
4. 任一方在候选池选择 2–10 道菜，新增一条共同收藏。
5. 进入转盘点「转一下」；另一方进入转盘点「同步结果」，核对答案一致。
6. 点击「确认今天吃它」，在投喂日记检查记录、拍板人和统计。
7. 在候选池对一道菜点「就吃它」，检查手动点菜记录。
8. 修改昵称与口味偏好，确认另一方看到房间内新昵称。
9. 测试「解除关系」，确认双方重新进入后均为未绑定状态。

## 6. 发布前检查

- 在公众平台补充小程序名称、图标、类目和隐私保护指引。
- 将 A、B 加入体验成员，分别在 iOS 与 Android 真机检查。
- 云开发控制台查看云函数日志，确认无索引缺失提示。
- 小程序代码上传前执行 `npm test`。
- 在开发者工具执行「代码质量」与「体验评分」。
- 上传体验版、提交微信审核，审核通过后发布。

## 常见问题

### 提示“服务暂时开小差”

优先检查云函数是否部署到开发者工具当前选中的环境，以及云函数日志中的具体错误。

### 历史/收藏列表提示缺少索引

按第 3 节建立组合索引，等待索引构建完成后重试。

### 两人无法绑定

确认两人使用不同微信账号、邀请码未超过 24 小时，且双方都不在其他未解除的房间中。

### 模拟器能打开但云能力不可用

`touristappid` 只能预览静态界面。必须替换为已开通云开发的小程序 AppID，并选择已创建的云环境。
