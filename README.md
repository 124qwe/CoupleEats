# 今天吃啥鸭 🦆

一款给情侣使用的吃饭决策微信小程序。原生 WXML / WXSS / JavaScript 实现，数据闭环全部运行在微信云开发中。

## 已实现

- **心意绑定**：A 生成 6 位邀请码，B 输入或从微信分享卡片进入；`openid` 鉴权，一间房最多两人。
- **候选池**：火锅、日料、家常菜、烧烤、快餐、甜品等 24 道内置选择；支持搜索、分类和最多 10 道候选。
- **共同收藏**：情侣可以新增、编辑、删除爱吃的店或菜，双方共享。
- **云端转盘**：结果在云函数中随机生成并持久化；另一方点「同步结果」得到同一答案。
- **两种决定方式**：转盘抽选，或在候选池直接点「就吃它」。
- **确认与轮换**：确认后记录本次拍板人，下一轮提示换 TA 来决定。
- **投喂日记**：按今天、本周、全部查看，含本周次数、累计翻牌和转盘次数。
- **个人页**：昵称、口味偏好、绑定状态、共同邀请码、收藏入口和解除关系。
- **真机适配**：安全区、云环境动态选择、主包小于 2 MB，无第三方前端依赖。

## 工程结构

```text
miniprogram/                 小程序端
  data/catalog.js            内置分类与菜品
  pages/                     首页 / 绑定 / 候选池 / 转盘 / 历史 / 我的
cloudfunctions/              云函数
  auth/                      openid 登录及用户初始化
  room/                      房间创建、加入、查询、解除
  favorites/                 共同收藏 CRUD
  spin/                      云端随机、同步、确认
  records/                   手动翻牌、历史与统计
  profile/                   昵称与口味偏好

database.rules.json          推荐数据库安全规则
database.collections.json    集合与索引清单
```

## 快速启动

完整部署步骤见 [`docs/DEPLOY.md`](docs/DEPLOY.md)。最短流程：

1. 微信开发者工具导入仓库根目录；将 `project.config.json` 的 `appid` 改成正式小程序 AppID。
2. 开通云开发环境。
3. 创建 `users`、`rooms`、`favorites`、`spins`、`records` 五个集合并建立索引。
4. 对六个云函数分别选择「上传并部署：云端安装依赖」。
5. 编译后使用两位微信用户完成绑定与真机联调。

小程序使用 `wx.cloud.DYNAMIC_CURRENT_ENV`，无需在代码中写死环境 ID。

## 本地检查

```bash
npm test
```

检查 JavaScript 语法、页面/云函数完整性、菜品数据唯一性和 2 MB 主包限制。

## 数据安全

客户端没有数据库直连权限。`database.rules.json` 默认拒绝客户端读写，所有数据操作经云函数执行；云函数用微信上下文中的 `OPENID` 校验当前用户与房间成员关系，客户端传入的 openid 不会被信任。
